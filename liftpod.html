LiftPod

Hackathon project · built with Benton Tameling

A native iPhone workout tracker that turns an AirPod into a rep sensor. Strap the AirPod to a dumbbell and LiftPod streams its IMU over Core Motion, learns the movement you're repeating, counts complete reps, groups them into sets, and estimates movement speed — then optionally hands the set summary to an LLM coach for RIR, rest, and next-set suggestions.

Swift SwiftUI Core Motion IMU / 50 Hz PCA OpenAI API Hackathon

overview

AirPods with head tracking carry a full IMU — acceleration, rotation rate, gravity, and attitude — exposed to apps through CMHeadphoneMotionManager. LiftPod repurposes it: instead of tracking your head, it tracks the weight. No extra hardware, just earbuds most people already own.

The core design rule is that the counter owns rep identity. Speed estimation, phase analysis, exercise classification, and AI coaching all consume counted reps as supporting evidence, but none of them can create or remove a rep on their own. A metric that fails its quality checks simply shows as unavailable.

signal pipeline

1

Capture

Raw AirPod motion callbacks flow through a provider abstraction into CaptureModel, which owns ordered event routing and app lifecycle.

2

Resample & featurize

Irregular callbacks are resampled onto a deterministic 50 Hz timeline and filtered into world-relative acceleration, rotation, and gravity features. Clock gaps, backward timestamps, or orientation failures cut the evidence epoch so a rep can never span missing data.

3

Learn & match cycles

An exercise-independent detector learns a 64-frame movement pattern, tracks ordered progress through it, and only authorizes a rep once coverage, duration, endpoint agreement, and repeatability all pass. Early qualifying cycles are backfilled once the pattern locks in.

4

Group into sets

Manual mode uses Start/End Set boundaries. Automatic mode runs one continuous capture: repeated cycles open a set, sustained quiet becomes rest, and a coordinator seals each set once its boundary resolves.

5

Speed & phase metrics

Whole-rep speed comes from a reconstructed 3D path, gated on acceleration bias, endpoint velocity, displacement closure, and boundary sensitivity. After the set, gravity-aligned and PCA cycle proposals are matched one-to-one to counted reps to split average up vs. down speed.

6

Coach

An optional compact set summary is sent to the OpenAI Responses API with a structured-JSON schema, returning estimated RIR, a coaching note, rest time, and an editable next-set prefill.

recording & replay

Every set is recorded as a replayable bundle. The same ordered inputs and frozen configuration drive both live processing and replay, and manifests carry hashes so a replay can be verified bit-for-bit against the original run — which made it possible to iterate on the detector offline against real recordings.

limitations

  • Rep detection depends on a consistent AirPod mount and reasonably repeatable movement.
  • Speed is measured at the AirPod, not the barbell, and is withheld when drift or orientation checks fail.
  • Exercise classification is experimental and never controls the counter.
  • The simulator can test logic and UI, but real accuracy needs physical recordings across people, tempos, and mounts.
