5-Stage RV32I Pipelined CPU

A classic five-stage (IF / ID / EX / MEM / WB) RISC-V processor in SystemVerilog, targeting a Basys3 (Artix-7 XC7A35T). Implements RV32I less FENCE, ECALL and EBREAK — about 35 instructions, with full forwarding, load-use interlocks and branch flushing.

overview

The pipeline is textbook in shape and deliberately un-clever in its choices, but every structural claim about it is measured rather than asserted. The testbench counts the cycles the execute stage sits empty after a redirect and the cycles the front end is held for a load-use hazard, so the penalties below come out of simulation rather than out of design intent.

Each stage module owns the pipeline register on its output boundary, so the inter-stage structs (if_id_t, id_ex_t, ex_mem_t, mem_wb_t) are always already registered by the time a stage receives them. That one convention removes most of the ambiguity about where a value lives on any given cycle.

design decisions

The choices below are the ones that were not forced by the shape of a five-stage pipe.

Branches resolve in EX, not ID2-cycle penalty
Branch operands need forwarding, and forwarded values only exist in EX. Resolving there costs a measured 2 cycles on a taken branch: fetch invalidates the instruction entering IF/ID, and hazard_unit flushes ID/EX.
Decode resolves everything; EX never sees instruction bits
id_ex_t carries a fully-decoded alu_op, operand selects and a jalr flag rather than the raw opcode. All ISA knowledge stays in one module.
A separate target adder in EX
The main ALU is already busy on every control-flow instruction — comparing operands for a branch, or computing PC+4 for a jump — so the redirect target gets its own adder with a 2:1 base mux (PC for branch/JAL, forwarded rs1 for JALR).
JALR's mandatory LSB clear is unconditionalsaves a mux
B- and J-type encodings have no imm[0] bit at all, and the PC is always 4-aligned, so forcing bit 0 low is a no-op for branches and JAL. One less mux.
Forwarding resolves once, in EX
ex_mem_t.rs2_data holds the forwarded store data, so MEM never re-forwards. The muxes sit ahead of operand select, so store data and the JALR target base get bypassed too — both are consumed outside the ALU datapath.
reg_write is suppressed in decode when rd == x0
One fix makes the register file write guard, the write-through bypass and the forwarding unit all safe at once, instead of each needing its own != 0 test.
The register file bypasses writes to reads
A WB write is visible to an ID read in the same cycle. Without this, an instruction three after its producer reads a stale value — the producer retires before the consumer reaches EX, so no forwarding path can rescue it.
Six branch types collapse to three ALU ops
funct3[0] is an "invert the result" bit across every pair (BEQ/BNE, BLT/BGE, BLTU/BGEU), so decode selects only SUB, SLT or SLTU and EX applies the inversion.
Load formatting happens in WB, not MEM
The DMEM read is synchronous, so the loaded word does not exist until it has crossed into MEM/WB — the BRAM's own output register is that pipeline register. mem_wb_t therefore carries mem_funct3 and addr_lsb so WB can do lane select and sign extension.
No cache
The entire memory is on-chip BRAM at single-cycle latency and the Basys3 has no external DRAM. A cache would add tag arrays, miss handling and stall paths for zero speedup.

verification

Each block is checked against an independently written reference model, with constraints that steer stimulus toward the cases that actually break hardware rather than relying on uniform random. Every testbench also asserts its own coverage floor and fails if the interesting scenario did not occur often enough — a test that silently stops exercising its target is worse than no test.

End-to-end programs

tb_top runs four hand-assembled programs — built by field-level encoder functions rather than hex literals — with a reset between each:

  • Hazards. EX→EX and MEM→EX forwarding, regfile write-through, load-use stall, branch/JAL/JALR flushes, x0 write suppression, all R- and I-type ALU ops.
  • Branch comparisons. All six compare types with operands (−1 and 1) chosen so signed and unsigned disagree.
  • Sub-word memory. SB/SH/SW into every byte and halfword lane, LB/LBU/LH/LHU back out, plus a load feeding a store's data.
  • Penalty measurement. Counts the cycles EX sits empty after a redirect and the cycles the front end is held for a load-use hazard.

An X-propagation watchdog fails the run if the register file is ever written with unknown bits.

Mutation testing

Passing tests only mean something if they can fail. Making SLTU signed in alu.sv fails exactly the three unsigned-comparison checks in tb_top and nothing else; restoring it returns the suite to green.

code

hazard_unit.sv is the whole of the stall-and-flush policy — the two behaviours the simulator above visualises, in fifty lines of purely combinational logic.

rtl/hazard_unit.sv
module hazard_unit
    import pipeline_pkg::*;
(
    // ID stage: which registers the instruction currently in ID will read
    input  logic [4:0] id_rs1_addr,
    input  logic [4:0] id_rs2_addr,
    input  logic       id_uses_rs1,
    input  logic       id_uses_rs2,

    // EX stage
    input  id_ex_t     id_ex_reg,
    input  logic       branch_taken,

    output logic       stall_if,   // hold pc and if_id_reg
    output logic       bubble_id,  // clear id_ex_reg (load-use)
    output logic       flush_id    // clear id_ex_reg (branch taken)
);

    logic load_in_ex;
    logic rs1_conflict, rs2_conflict;
    logic load_use;

    assign load_in_ex = id_ex_reg.valid &&
                        id_ex_reg.mem_read &&
                        (id_ex_reg.rd_addr != 5'd0);

    assign rs1_conflict = id_uses_rs1 && (id_ex_reg.rd_addr == id_rs1_addr);
    assign rs2_conflict = id_uses_rs2 && (id_ex_reg.rd_addr == id_rs2_addr);

    assign load_use = load_in_ex && (rs1_conflict || rs2_conflict);

    assign stall_if  = load_use;
    assign bubble_id = load_use;
    assign flush_id  = branch_taken;

endmodule: hazard_unit

known limitations

Deliberate, and each one is a trade rather than an oversight.

No store-data forwarding (MEM→MEM)
A load immediately followed by a store of the loaded value costs one stall cycle. Keeps the bypass network to two sources.
No misaligned-address traps
JALR can produce a target that is 2-mod-4; the spec wants an instruction-address-misaligned exception. Exceptions are out of scope, so fetch silently truncates instead.
The hazard unit is conservative on stores
A store's rs2 is not needed until MEM, but the stall fires in ID regardless.
IMEM and DMEM are declared inline
In fetch.sv and mem_stage.sv. IMEM must move to its own dual-port module before a UART loader can write it.
